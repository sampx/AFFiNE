    `pnpm` 的 workspace 功能允许你在单个仓库中管理多个子项目（monorepo），并且可以轻松地在这些子项目之间共享代码和依赖。它非常适合用于像你当前的项目结构这样的多包架构。 ### 1. `workspace:*` 协议的作用 当你在 [package.json](file:///Users/sam/Coding/sampx/BlockSuite-DS/packages/theme/package.json) 中使用 `"workspace:*"`，例如： ```json { "dependencies": { "@toeverything/theme": "workspace:*", "@toeverything/components": "workspace:*" } } ``` 这意味着： - `pnpm` 不会从远程 npm 注册表安装这些依赖。 - 它会在本地工作区中查找对应的子项目，并将其作为本地链接引用。 - 这样做的好处是：你可以直接使用本地开发中的版本，修改后立即生效，无需发布新版本或手动 `npm link`/`yarn link`。 --- ### 2. `pnpm install` 是否安装所有子项目的依赖？ **简短回答：是的，但不是一次性全部安装，而是根据依赖关系按需安装。** 详细解释如下： #### ✅ 当你运行 `pnpm install` 在根目录时： 1. **它会遍历所有 workspace 包** 根据 `.pnpm-workspace.yaml` 文件中定义的路径（如 [packages/**](file:///Users/sam/Coding/sampx/BlockSuite-DS/packages/components/README.md) 和 [scripts/**](file:///Users/sam/Coding/sampx/BlockSuite-DS/scripts/README.md)），它会找到所有的子项目。 2. **每个子项目的依赖都会被安装** 每个子项目都有自己的 [package.json](file:///Users/sam/Coding/sampx/BlockSuite-DS/packages/theme/package.json)，`pnpm` 会为每个子项目安装其声明的依赖项。 3. **依赖会被提升到根 `node_modules`** pnpm 默认采用“严格模式”（即每个子项目有自己独立的 `node_modules`）。但如果你启用了 `shared-workspace-lockfile: true`，那么所有公共依赖会被提升到根目录的 `node_modules`，避免重复安装。 4. **子项目之间的依赖自动链接** 如果 A 子项目依赖 B 子项目且使用了 `workspace:*`，则 B 不会被单独安装，而是直接链接本地文件。 --- ### 3. 示例说明 以你的 `.pnpm-workspace.yaml` 为例： ```yaml packages: - 'packages/**' - 'scripts/**' ``` 这表示： - 所有位于 `/packages/` 和 `/scripts/` 下的子目录都将被视为 workspace 成员。 - 每个子目录应该包含一个 [package.json](file:///Users/sam/Coding/sampx/BlockSuite-DS/packages/theme/package.json)，以便 pnpm 能识别它是一个包。 --- ### 4. 常见命令与用途 | 命令 | 说明 | |------|------| | `pnpm install` | 安装整个 workspace 中所有子项目的依赖 | | `pnpm add <pkg> -w` | 在整个 workspace 层级安装一个依赖（通常是一些工具，如 TypeScript、ESLint） | | `pnpm add <pkg> --filter <package-name>` | 只在指定的子项目中安装依赖 | | `pnpm run <script> --recursive` | 在所有子项目中运行某个 script（如 [build](file:///Users/sam/Coding/sampx/BlockSuite-DS/packages/theme/vite.config.ts#L12-L29) 或 [test](file:///Users/sam/Coding/sampx/BlockSuite-DS/packages/components/vitest.config.ts#L6-L9)） | --- ### 5. 小贴士 - 如果你想查看 workspace 中有哪些包，可以运行： ```bash pnpm ls --depth=10 ``` - 如果你想更新某个 workspace 内部依赖的版本，只需在对应子项目的 [package.json](file:///Users/sam/Coding/sampx/BlockSuite-DS/packages/theme/package.json) 中更改版本号并重新安装即可。 --- 如有需要我可以为你演示如何在一个子项目中引入另一个子项目。

  • BlockSuite Framework Overview | BlockSuite
    People who are really serious about editor should make their own framework.BlockSuite is a toolkit for building editors and collaborative applications. It implements a series of content editing infrastructures, UI components and editors independently.You can consider BlockSuite as a UI component library for building various editors, based on a minimized vanilla framework as their runtime. With BlockSuite, you can:Reuse multiple first-party BlockSuite editors:PageEditor: A comprehensive block-based document editor, offering extensive customization and flexibility.EdgelessEditor: A graphics editor with opt-in canvas rendering support, but also shares the same rich-text capabilities with the PageEditor.Customize, extend and enhance these editors with a rich set of BlockSuite components and examples. All BlockSuite components (including editors) are native web components, making them framework-agnostic and easy to interop with popular frameworks.Or, build new editors from scratch based on the underlying vallina framework.

    BlockSuite 技术架构深度分析BlockSuite 是 AFFiNE 的核心编辑器框架，基于现代 Web 技术栈构建，支持实时协同编辑、丰富的块级内容和可扩展的插件系统。本文档将深入分析其架构设计、技术栈选择和开发实践。🏗️ 整体架构概览BlockSuite 采用分层模块化架构，主要分为两大层次：1. Framework 层 (blocksuite/framework/)提供底层基础设施和核心抽象，包括：@blocksuite/store - 数据存储核心功能: 基于 Yjs 的 CRDT 数据存储和状态管理核心概念:Store: 管理 Block 生命周期的核心类Block: 文档中的基本单元，包含数据模型和视图Schema: 定义 Block 的结构和约束Extension: 可插拔的功能扩展系统技术特点:支持实时协同编辑 (基于 Yjs CRDT)响应式状态管理 (@preact/signals-core)事务性操作和撤销/重做类型安全的数据模型 (Zod 验证)@blocksuite/std - 标准库功能: 提供编辑器标准功能和工具集核心模块:Command: 命令系统，支持链式调用和撤销Selection: 选择状态管理Event: 事件系统和键盘快捷键Clipboard: 剪贴板操作View: 视图管理和渲染设计模式: 依赖注入容器 + 扩展系统@blocksuite/sync - 同步引擎功能: 多端数据同步和冲突解决架构:DocEngine: 管理主文档和影子文档的同步DocPeer: 负责单个数据源的同步逻辑DocSource: 抽象的数据源接口同步策略: 主优先策略 (main-first strategy)@blocksuite/global - 全局配置功能: 全局配置、工具函数和类型定义内容: 环境检测、调试工具、通用类型2. Affine 层 (blocksuite/affine/)提供具体的编辑器实现和用户界面组件：blocks/ - 块组件实现每个块都是独立的包，包含完整的功能实现：核心块类型:paragraph: 段落文本，支持多种标题级别list: 有序/无序列表，支持嵌套code: 代码块，支持语法高亮image: 图片块，支持多种格式table: 表格，支持复杂的表格操作database: 数据库视图，支持多种视图模式
